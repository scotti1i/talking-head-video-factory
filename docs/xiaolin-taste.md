## 0. 三句话说清目标

1. 观感目标是 **Apple / Notion 的现代扁平 + 小Lin 的连续视觉叙事**：纯色面、发丝线、靠明度和留白分层；同一个知识对象在画面上持续生长，不是一页页换 PPT。（2026-09-02 Scott：实体块「安卓 15 年前的风格」；2026-09-03「整体不错但八股」）
2. **人说话是主画面**，包装是伴奏：右侧板子只在有内容时存在，人物不为空板子让位。（2026-09-04 Scott：「第一秒右边黑色大板子不可接受」）
3. **节奏快是对的**：每 4 秒有变化，前 10 秒每秒一个动作；八股不是因为密，是因为真实信息少、点缀少、尺度不跳、模板顺序雷同。（2026-09-03 Scott 纠正我的「让人多说话」诊断）

## 3. 什么可以造、什么必须真

（2026-09-02 Scott 定，说明书「编排纪律 4」）**证据档**：口播在引用事实来源时，画面必须是真实截图 / 真实数据并写来源。**理解档**：新闻、人物、产品、教程、场景的「那种东西」允许生成或合成，不标「示意」，只在 `origin` 记录；不得冒充具体来源。第三方视频：只取屏幕演示段，裁掉画中画、人脸、账号头像。

## 5. 编排判断（写分镜前先过一遍）

1. **一个主命题**，能用一句口播原话说出来；开头 3s 内出话题，10s 内出可信度（官方数据 / 真实页面 / 排行榜）。
2. **保留口播叙事顺序**（`sourcePolicy: preserve-order`），除非 Scott 明说可重排；「把结论提到开头」是 Codex 09-05 被否的做法。
3. **抖音向**：1.1 倍速、不焦虑开场、不绝对化；片长不设数字上限（09-07 Scott 删掉 ≤100s），按注意力剪：每一段都要回答「观众为什么还不划走」。
4. **DBS 自审**（`~/.codex/skills/dbs-hook` / `dbs-script-flow`）：话题 + Hook + 可信度三要素；悬念不给答案；口播友好；每段之间无逻辑断裂；无重复表述。
5. **B-roll 三个位置优先**：钩子后 2–4s 的通栏「视觉冲击」、核心机制段的面板「看它在干活」、结尾预告段。
6. **每 4 秒一个变化，每 30–45s 一次休息**，两者同时成立。竖屏 `studio-portrait` 里「休息」= 回到 full 态纯脸 ≥4s，不要求 B-roll。
7. **素材来源红线（2026-09-07）**：品牌广告画面和外站爆款片段一律不上抖音版；公开网页自己用 Playwright 录（`jobs/gpt6-astra-games-20260907/tmp/record.mjs` 可复用），只有作者视频的内容用即梦生成同类画面。网页录屏只留「实录区」（demo 视频 / 画布 / 表格本体），裁掉页面大标题、品牌栏、营销文案——整版精修页面在审片人眼里就是广告页（2026-09-07 v7 审片打回「Browser in motion」页）。
8. **studio 皮肤下人物出镜**：full + wide 时长占比目标 ≥ 40%（编译器打印），板子在最后一个元素出现后 2.5s 内回全画幅。
9. **相邻舞台场景间隔 ≥0.6s，贴脸胶囊在人物回全画幅 ≥0.5s 后（2026-09-07）**：模板入场提前 0.3s、退场拖后 0.3s，间隔小于 0.6s 前一块板子的淡出一定压在后一块的淡入上（v10 成片 89.4–89.8s 对比卡压目录面板；编译器已警告）；独立审片只把 <1.5s 入场算过程帧，退场交叠它不一定报，每版成片自己再看切点帧。
10. **竖屏 `studio-portrait`（2026-09-07 Scott：口播为主、动画辅助、注意力在人身上）**：画布 1080×1920，人物永远铺满，full（原片）/ focus（推近，整个头在画面里）/ split（上移，下半区放 16:9 第三方面板）三态，没有卡片化人物；内容只在脸下方下区（y 990–1300），贴脸胶囊只在 full 态；不放通栏 B-roll；开场主题卡 `title.layout=topic`。取景按每条片的人脸高度调 `plan.canvas.{focusScale,focusShift,splitShift}`（默认 1.1/270/300；脸偏低的片用 1.0/330/440）。分镜用原片秒写在 `jobs/<slug>/data/scenes.py`，`scripts/portrait_plan.py` 换算 + 推导人物时间线。spec `docs/skin-studio-portrait-spec.md`，参照 `docs/exemplars/astra-computer-use-portrait`。
11. **进爽点节奏（2026-09-08 Scott：「砍得更多、更紧凑、进爽点太慢、解释性太多」）**：5s 内观众要看到这条片最抓人的画面或最锋利的一句，铺垫式开场（自我介绍 / 「有没有发现一件事」/ 两个问题引入）一律删或后置；「解释性」三类一律 reject——对上一句的再解释、过程细节（怎么点怎么切）、预防式回答没人问的问题——除非它本身就是爽点。删是首选，重排要 Scott 点头（§5-2）。首例 `docs/reviews/2026-09-08-openai-demo-tight-cut.md`（306.7s → 232.6s）。

## 6. 审片清单（独立审片代理逐条打分；任一 ✗ = 不过）

看的是 `qa/review-<version>/` 的静帧板。每条答 ✓ / ✗ + 一句证据（帧时间）。

1. 开场 3s：正脸 + 话题可读；标题没有压在人脸上。
2. 任何一帧：右侧板子不空（有板必有内容）；没有孤零零一个胶囊占一整块板。
3. 任何一帧：元素不压人像、不互相重叠、文字不溢出容器；强调实底上的字可读。
4. 第三方素材帧：无人脸、无账号头像、无摄像头画中画；抖音向成片不含品牌广告页面 / 官方宣传片 / 外站爆款演示片段（2026-09-07 机器标记事故）。
5. 人物换位：20s 内 ≤4 次；居中时两侧无杂物。
6. 视觉休息：每 45s 内至少一次 B-roll / 通栏 / 标题。
7. 文字：只有口播原话或最短直译；没有英文装饰词、自造金句、「示意」「我的录屏」类说明角标。
8. 材质：纯色面 + 发丝线，没有渐变高光 / 发光 / 拟物。
9. 抖音向：开头不是焦虑 / 替代人叙事；全片没有可划走的段落（连续 8s 以上没有新信息、新画面或新情绪 = 尿点）。
10. 与参照成片相比，这条片有自己的签名（背景板 / 开场手法 / 默认人物侧至少一项不同）。

## 7. 停机规则（比「继续想办法」更高优先级）

- **只有 `scripts/stage-render.mjs` 能产出成片**。Chromium 起不来、工作区无标记、依赖缺失 → 停下来报告原因和已试过的两种修法；**禁止自造 FFmpeg / 录屏 / 其它后备渲染链，禁止用「像的」模板顶替**。（2026-09-05 Codex 起不了 Chromium 后自造静态卡片版 v1–v4，被 Scott 当场否掉）
- **渲染前必须看图**：`stage-stills` 出板 → 自己看 → 独立审片 → 样片给 Scott → 成片。任何一步没做不许进下一步；`--final` 没有 `qa/review-<version>.json`（审片通过）+ `qa/approval-<version>.json`（Scott 通过）直接拒绝。
- 门禁全绿 ≠ 创作合格。汇报里不许把技术门禁写成质量结论。
